C2PA Image Proof Schema v1

Canonical schema URL: https://anchr-spec.org/spec/proof/c2pa-image/v1

This schema identifies C2PA image or media evidence with optional GPS, timestamp, nonce, ProofMode, and advisory content-relevance checks.

Predicate Shape

The predicate describes the requested media evidence and deterministic constraints an Oracle must apply to signed metadata. 

{
  "locationHint": "Shibuya, Tokyo",
  "expectedGps": { "lat": 35.6595, "lon": 139.7004 },
  "maxGpsDistanceKm": 0.5,
  "freshnessSeconds": 600,
  "challengeNonce": "optional visible nonce",
  "requiredFactors": ["c2pa", "gps", "timestamp"]
}
Field Meaning
locationHint Human-readable target location or scene description.
expectedGps Expected latitude and longitude for signed media metadata.
maxGpsDistanceKm Maximum Haversine distance from expected GPS coordinates.
freshnessSeconds Maximum accepted age for signed capture metadata.
challengeNonce Optional nonce that should be visible in the media.
requiredFactors Required deterministic checks, such as c2pa, gps, and timestamp.

Proof Payload Shape

The proof payload contains the media bytes or encrypted attachment references, plus optional ProofMode sidecar material. 

{
  "media": "<bytes or encrypted attachment reference>",
  "filename": "signed-photo.jpg",
  "proofmode": "<optional ProofMode archive reference>",
  "notes": "optional Provider notes"
}

Response Data Shape

On success, verifiers expose only the facts needed to explain the verdict: 

{
  "c2pa": {
    "available": true,
    "hasManifest": true,
    "signatureValid": true,
    "gps": { "lat": 35.6595, "lon": 139.7004 },
    "timestamp": 1770000000
  },
  "proofmode": {
    "signatureValid": true,
    "gps": { "lat": 35.6595, "lon": 139.7004 }
  },
  "warnings": []
}

Verification Requirements

  • Verify the C2PA manifest signature chain for the submitted media.
  • Require the manifest asset hash to match the submitted media bytes.
  • Compare signed GPS coordinates to expectedGps using Haversine distance and maxGpsDistanceKm.
  • Reject stale signed timestamps when freshness is required.
  • Verify ProofMode signatures when ProofMode evidence is submitted or required.
  • Treat AI content relevance as advisory unless a future schema version makes that factor deterministic.
  • Fail closed when a required verifier or companion binary is unavailable.
